- **Wrote an automated end-to-end test** that starts the server, checks its health, signs a user up, reads a protected page, and confirms the security block — all by itself. We deliberately broke it in two ways to confirm it actually catches failures. We also added a **single "run all checks" command** so the whole safety net (now 12 checks) runs at once.

## Addendum (23 July) — Adversarial re-review caught two real issues, both fixed
Before signing off the foundation, we deliberately re-reviewed the whole batch of changes as if a hostile outside auditor were trying to break it — "assume it's wrong until proven otherwise." Two genuine problems surfaced, and both are now fixed and verified:

- **A privacy/access-control gap was closed.** An earlier change had correctly locked *one* candidate screen so a logged-in user could only see their **own** data — but six sibling screens (profile summary, skills, completeness, headline, and two data-update actions) had been left open, meaning one candidate could have viewed, or even altered, **another** candidate's information by changing an id in the address. We applied the same ownership check to **all** of them through a single shared rule, and upgraded our automated test to prove every one of the eight is now locked (previously it only checked the one). *Note: strictly this is "security" work that belongs to the next phase — but since a partial fix was already in this batch, leaving it half-done behind a green checkmark was the more dangerous option, so we finished it now and documented the decision.*
- **A hidden "works on my machine" trap was removed.** One screen quietly relied on two software libraries that were installed on the current machine but **never officially listed** in the project. It built fine here, but a brand-new setup (or the live server) would have failed. We've now formally listed them at their exact current versions and confirmed a clean, from-scratch install succeeds — so the "repeatable setup" guarantee is now genuinely true.

All 11 automated checks (excluding the machine-specific end-to-end one) pass after these fixes. No user-facing behaviour changed; these were correctness and safety fixes.
