## What got done this period
- **The app can now point at any server by changing one setting.** Before, the web app had the local test address (`localhost:5000`) written directly into ~47 different files, and the backend had the AI service's address hard-wired in 15 places. That meant "put it on a real server" required hand-editing dozens of files — error-prone and a guaranteed source of broken deploys. Now there is a **single setting on each side**; everything else follows automatically.
- **Fixed two hidden bugs found along the way:** a document-upload (OCR) call and a profile-badges call were pointed at addresses that didn't exist, so they would have silently failed in production. Both corrected.
- **Added an automatic safeguard** that fails the build if anyone ever re-introduces a hard-wired address — so this problem can't quietly come back.

## What this means for you
- When we move to staging/production, switching the app to the real domain is now a **one-line configuration change per side**, not a risky code edit — this directly de-risks the upcoming deployment.

## Addendum — Correctness pass (same week)

Alongside the deployability work above, we did a focused pass on the "it looks like it works but quietly doesn't" class of problems and closed several real ones:

- **Fixed a hidden auto-logout.** Users were being silently signed out roughly every 15 minutes — the app wasn't correctly reading the server's "here's your refreshed session" response, so it kept letting the login quietly expire. This is now fixed; sessions stay alive as intended.
- **Fixed the admin "Agencies" approval screen.** The screen displayed, but approve / reject / list all failed behind the scenes (it was sending the wrong sign-in credential). Admins can now approve and reject agencies again.
- **Fixed login & sign-up reading the server incorrectly.** The same underlying mismatch affected the login, sign-up and two-factor screens — they now read the server's responses correctly.
- **Confirmed document-validation results reach the system** (the earlier wrong-address issue), and removed a dead leftover code path that pretended to call a resume service that doesn't exist.
- **Added an automatic end-to-end check** that spins up the real system on a disposable database and walks the actual journeys — refresh a session, approve an agency, sign out other devices, start a chat, receive a document-validation result — proving none of them silently dead-ends. It runs on every build.

### What this means for you
- Everyday sign-in, staying logged in, and the admin agency-approval workflow now work reliably — these were quietly broken before and would have surfaced as confusing "it's not doing anything" reports from real users.
