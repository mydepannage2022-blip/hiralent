## What got done this period
- **Fixed the "it installs differently on every machine" problem.** The project had leftover setup files from two different package managers (six in total), which is a classic cause of "works on my machine" bugs. We settled on **one** tool (pnpm) and removed the duplicates, so every developer and the server now install the exact same versions.
- **Removed dead weight from the code.** Cleared out several unused and duplicated libraries the app was carrying (including a duplicate password-security library and unused server/search components) — smaller, faster, fewer moving parts to break.
- **Standardised the password library safely.** We proved with automated tests that existing user passwords still log in correctly after the change — no one gets locked out.
- **Fixed two files the website was missing** that would have stopped the front-end from building, and **repaired two corrupted configuration files** in the AI services.
- **The server (back-end) now builds cleanly — a major milestone.** It previously had 81 code errors blocking a proper build; all are now fixed, and we turned on a safeguard so the build will refuse to proceed if any new error is introduced. Several of these weren't just cosmetic — a few were **hidden crashes** waiting to happen (e.g. the "recommended jobs" screen and part of the CV-upload flow would have errored for real users). Those are now fixed and wired to the actual job-matching engine.
- **The website (front-end) now builds cleanly too — the other major milestone this week.** It had 58 code errors blocking the build; all are fixed with real corrections (no shortcuts or disabled safety checks). As with the server, a couple weren't cosmetic: the "verifying your email" and a camera-photo-in-chat feature had **hidden bugs** that are now fixed, and the public "Find Jobs" page was quietly making sign-in-only requests for logged-out visitors — that's now clean. We also removed one leftover old page that was silently breaking the website build.
- **Added automated checks** that will catch these problems again if they ever creep back — including two new build checks (one for the server, one for the website), each deliberately tested by breaking the build on purpose to confirm it catches errors.
- **Cleaned up the configuration and closed two silent hazards.** (1) The server's database settings contained a dangerous line that, in the wrong situation, could have let a routine developer command **wipe the main database** — we neutralised it and documented the safe setup. (2) The Google/Firebase login component would **crash the whole server on startup** if its keys were missing; we changed it to fail gracefully (only the login feature is affected, and only if it's actually used). (3) Removed a corrupt line and a duplicated setting from the server config. (4) Created **"example" configuration templates for every service** (with all secret values blanked out) so a new developer or the production server knows exactly what to fill in — no more guessing or silently running on local defaults. A new automated check enforces all of this and was tested by breaking it on purpose.

- **Cleared out dead code and committed junk from the repository.** Removed ~15 confirmed-unused files (an old duplicate startup file, an unused health-check, a duplicated scheduler, AI-service backup copies and throwaway test scripts, and several orphaned/duplicate website components), and stopped the project from tracking accidental clutter (log files, a stray local test database, Windows shortcut files, old schema backups) — with a rule added so they can't sneak back in. Also fixed two wiring issues: one internal route was registered **twice**, and a **developer-only testing endpoint was reachable in production** — it's now locked to development only. Nothing users see changed.
- **Our build safety-net paid off mid-cleanup.** One component looked unused but was actually still wired to a developer test page; the automated website build caught it immediately, so we kept that file and removed only the genuinely-dead copy. This is exactly the kind of mistake the checks exist to catch — verified, not assumed.
